# 时光屋 1.2.0 · 日常训练与我的动作组

## 问题与改动

首页原先把日常课交给临时加练排序，只有同模式数量限制，没有必需模式覆盖；基础动作同分时靠 id 排序，器械只作为过滤条件。另有旧安全评估把用户选择的日常强度直接降为低强度而不说明。哑铃弯举原来的「拉」标签也会让它占掉背部主训练位置。

现在日常全身力量按髋铰链、推、拉、蹲、核心顺序选择，时间短时保留前面的主动作。主动作优先采用通过安全过滤的已选器械，辅助放后；未填写器械只能使用自重选择，不再视为全部器械可用。徒手始终可以作为回退。新增壶铃硬拉、TRX 反向划船、哑铃推举、壶铃摇摆、开合跳、徒手深蹲和俯卧撑条目；新条目提供文字要点，暂未新增动画。壶铃摇摆不进入初级自动加练。

25 分钟预算的日常力量默认至多 5 动作、每动作至多 3 组，主动作 RPE 7–8；按动作工作时间、休息、切换与个人节奏估算，必要时减少组数/动作数。器械选择不意味着必须用完全部器械。示例测试（无伤痛/近期训练，壶铃、TRX、哑铃）：壶铃硬拉、哑铃卧推、TRX 划船、杯式深蹲、平板支撑，主课约 23 分钟。8/15 分钟预算、恢复状态和安全设置可产生不同结果。热身和放松继续单独提示。

相同输入保持确定性，历史动作只小幅降权；安全、目标部位、周容量与恢复状态仍先于器械偏好。替换动作需同角色，AI 也只能在同角色候选中选择并保留本地组数与休息。已保存周期日历不自动重写。强度因评估/严重伤痛降级时，预览标题与说明明确给出原因。

## 我的动作组

入口：今天 → 我的动作组，或动作库 → 我的动作组。推荐课预览可「存为我的动作组」。

- 支持选择已有动作，也能创建个人动作并填要点/来源。
- 每动作保存组数、次数区间或计时秒数、每侧标记、RPE、休息、重量与动作备注。
- 支持顺序训练（A 的所有组后做 B）与循环训练（A→B→下一轮 A→B），可设置循环轮数与轮间休息。
- 支持上移、下移、编辑、删除；空名称、空动作组和无效处方不能保存。
- 保存后点「练这组」进入预览并开练。保存内容不会被推荐器改写。冲突的器械/伤痛条件会明确提示编辑。
- 个人动作不因加入动作组而变成自动推荐认可的动作。
- 重量、轮次备注在训练页显示并随训练结果保存；循环的动作后休息和轮间休息可暂停、重启恢复。

本地持久化使用 fitness_state.routinesV1，独立于原有记录与 workoutDraft。每个组合带版本与稳定 id。读取失败不重建覆盖；缺失动作显示错误，不悄悄替换。旧训练草稿没有 restAfter 字段时按 0 兼容读取。

## 训练依据与应用决策边界

2026-09-09 查询的 [ACSM 2026 更新](https://acsm.org/resistance-training-guidelines-update-2026/)强调规律训练、覆盖主要肌群和按个人情况调整；[官方摘要](https://www.acsm.org/wp-content/uploads/2026/03/Resistance-Training-Position-Stand-infographic.pdf)提供不同目标下的剂量要点。[ACE 动作库](https://www.acefitness.org/resources/everyone/exercise-library/)按器械和部位组织动作，提供操作说明。

本次使用这些原则组织候选；五个模式的具体顺序、RPE 7–8、75 秒休息和器械偏好分值是本 App 为日常短课设定的可测试默认值，并非指南规定所有人必须这样练。专业编排不等于堆砌复杂动作或每次随机变化。用户截图中的 16 kg 和总次数不能推导其他动作的合适重量，也没有自动写入用户处方。

## 验证与构建

- `scripts/run_domain_tests.sh`：原有领域测试及新 TrainingRoutineTest；器械进入实际动作、主模式覆盖、无器械回退、严重伤痛过滤、稳定排序、不同时间/节奏预算、循环顺序与休息估算。
- `scripts/qa_today_flow.py --serial emulator-5556 --output build/qa-20260909-existing`：原有流程回归，含锁屏/进程终止、提前结束、小屏及 130% 字体。
- `scripts/qa_routines_flow.py --serial emulator-5556`：新增编辑/持久化/循环 UI 回归。脚本恢复运行前偏好，仅允许显式选择的模拟器。
- `scripts/build_android_debug.sh`：直接 Android SDK 构建、沿用原调试签名，可覆盖安装。版本 1.2.0 / 2026090901。
- 修改前 Java 源码与清单位于 `build/before-20260909/`。测试模拟器在 `build/qa-avd/` 独立创建，不清除已有模拟器的数据。

具体 UI 通过结果见各自目录中的 ui-checks.json 与截图。交付 APK 为调试安装包，不包含 UI 测试 APK。
