# 科学动作库健身 App 产品规格 v0.1

日期：2026-06-14

## 1. 产品一句话

一个以科学动作库为底座的训练推荐 App：用户可以管理默认和自定义动作，用自然语言说“我想练背”，也可以在不知道练什么时选择强度后直接生成一套可开练的训练组合；推荐必须避开用户设置的伤痛部位，并标注科学依据。

## 2. 设计原则

1. 科学优先：默认动作、训练组合和推荐规则必须能追溯到权威指南或专业动作库。
2. 结构化优先：动作不是一段说明文字，而是一组可被筛选、推荐、替代和审计的字段。
3. 安全边界清晰：App 可以做风险避让和训练建议，不做医疗诊断、康复处方或疼痛治疗承诺。
4. 用户可控：外部保存和 AI 拆解的动作必须进入“待确认动作”，用户确认后才进入个人动作库。
5. 可坚持：推荐不追求复杂花哨，优先稳定、可执行、能长期坚持的方案。

## 3. 科学依据范围

### 3.1 指南底座

本产品第一版采用这些公开来源作为规则底座：

- ACSM 2026 阻力训练立场声明：强调一致性、覆盖主要肌群、渐进训练，以及阻力训练对力量、肌肥大、爆发力、耐力和身体功能的价值。
  - https://acsm.org/resistance-training-guidelines-update-2026/
  - https://acsm.org/science-spotlight-acsm-releases-new-position-stand-on-resistance-training/
- HHS Physical Activity Guidelines for Americans, 2nd edition：成人每周至少 2 天中等或更高强度肌力训练，覆盖主要肌群；低起点、慢进阶。
  - https://odphp.health.gov/sites/default/files/2019-10/PAG_ExecutiveSummary.pdf
- CDC 成人慢性病/残障体力活动建议：能训练的人仍应做每周至少 2 天主要肌群肌力训练；有慢病或残障时应咨询健康专业人士。
  - https://www.cdc.gov/physical-activity-basics/guidelines/chronic-health-conditions-and-disabilities.html
- WHO 2020 physical activity and sedentary behaviour guidelines：面向成人、老年人、慢病和残障人群的循证体力活动建议。
  - https://www.who.int/publications/i/item/9789240015128
- ACE Exercise Library：动作库结构参考，包括目标部位、器械、难度、步骤和图片说明。
  - https://www.acefitness.org/resources/everyone/exercise-library/
- NHS strength exercises：低门槛动作和家庭训练参考。
  - https://www.nhs.uk/live-well/exercise/strength-exercises/

### 3.2 产品内证据等级

每个动作和训练组合都必须有 `evidence_status`：

- `guideline_backed`：默认库动作，来自权威指南或专业动作库，并已结构化标注。
- `expert_reviewed`：用户自定义或外部保存动作，经过人工或专业审核。
- `user_unverified`：用户上传或外部保存后尚未审核，只能在个人库中展示，默认不进入自动推荐。
- `rejected_or_needs_edit`：拆解失败、风险标签不完整、来源不清或动作说明矛盾。

第一版不声称“最优动作”，只声称“符合已知指南原则的可执行推荐”。

## 4. 目标用户

主要用户：

- 有基础健身意愿，但不想每次自己编训练计划的人。
- 会在小红书、YouTube、B站、Instagram、TikTok 等地方看到动作，想快速保存整理的人。
- 有轻微不适或旧伤，需要推荐时避开明显刺激动作的人。

不作为第一版核心用户：

- 需要康复治疗的人。
- 专业健美备赛或竞技运动员。
- 需要实时姿态识别纠错的人。

## 5. MVP 范围

### 5.1 必做

1. 默认动作库
   - 按训练部位和动作类型分类。
   - 每个动作有图片/GIF/视频字段、讲解字段、风险标签和证据来源。
2. 自定义动作库
   - 用户可上传图片、GIF、视频链接和文字说明。
   - 自定义动作默认标记为 `user_unverified`。
3. 自然语言推荐
   - 支持“我想练背”“今天练腿”“肩不舒服但想练上肢”等输入。
   - 将自然语言解析为目标部位、目标类型、强度、器械条件和避让条件。
4. 不知道练什么
   - 用户选择低/中/高强度，App 生成一套可直接开始的训练组合。
   - 组合显示动作、组数、次数、休息、替代动作和推荐理由。
5. 伤痛部位设置
   - 设置肩、腰、膝、髋、肘、腕、颈、踝等部位。
   - 推荐时过滤或降权高风险动作。
6. 外部一键保存
   - iOS 使用 Share Extension。
   - Android 使用 Sharesheet / ACTION_SEND 接收文本、图片、GIF、视频或链接。
   - 自动提取封面、GIF/视频候选、标题、正文、字幕/OCR/转写文本。
   - 进入“待确认动作”，用户确认后入库。
7. 动作标心偏好
   - 用户可以对动作标心，表示喜欢或愿意优先练。
   - 标心动作在满足目标、伤痛避让、器械可用和证据规则后优先推荐。
   - 标心不能让高风险动作、不可用器械动作或未验证动作绕过安全过滤。

### 5.2 第一版不做

- 不做医疗诊断。
- 不承诺疼痛治疗。
- 不自动抓取付费或受限内容。
- 不绕过平台版权、登录或反爬限制。
- 不做实时摄像头姿态识别。
- 不直接让未验证动作进入自动推荐。

## 6. 信息架构

底部导航建议四个入口：

1. 训练
   - 命令输入：“我想练背”
   - “不知道练什么”按钮
   - 今日推荐组合
   - 最近训练记录
2. 动作库

3. 记录

   - 动作表现
   - 最近训练部位

4. 设置
   - 训练经验
   - 可用器械
   - 默认强度
   - 伤痛部位
   - 来源可信度偏好

## 7. 动作库分类

### 7.1 训练部位

- 背：背阔肌、斜方肌、菱形肌、竖脊肌
- 胸：胸大肌、胸小肌
- 肩：前三角、中三角、后三角、肩袖
- 腿：股四头肌、腘绳肌、小腿
- 臀：臀大肌、臀中肌、臀小肌
- 核心：腹直肌、腹斜肌、腹横肌、抗伸展、抗旋转
- 手臂：肱二头肌、肱三头肌、前臂
- 全身：复合动作、搬运、循环训练
- 活动度：髋、胸椎、肩、踝等活动度

### 7.2 动作类型

- 拉：水平拉、垂直拉
- 推：水平推、垂直推
- 蹲：双腿蹲、分腿蹲
- 髋铰链：硬拉类、臀桥类、髋伸展类
- 单腿：弓步、台阶、单腿稳定
- 旋转/抗旋转：转体、Pallof press、侧桥类
- 稳定：平板支撑、肩胛稳定、髋稳定
- 搬运：农夫走、单侧负重走
- 拉伸/活动度：动态热身、训练后拉伸、关节活动度

## 9. 默认动作库种子

第一版默认库不需要上千个动作，先放 60-100 个高质量、常见、可替代的动作。每个部位都要有器械、哑铃/杠铃、弹力带、自重版本。

### 9.1 背

- 高位下拉：垂直拉，器械，主练背阔肌
- 辅助引体向上：垂直拉，器械/自重
- 坐姿划船：水平拉，器械
- 哑铃单臂划船：水平拉，哑铃
- 弹力带划船：水平拉，弹力带
- 俯身 Y/T/W：肩胛稳定，自重/轻哑铃

### 9.2 胸

- 墙壁俯卧撑：水平推，自重，低强度
- 上斜俯卧撑：水平推，自重
- 标准俯卧撑：水平推，自重
- 哑铃卧推：水平推，哑铃
- 坐姿推胸：水平推，器械

### 9.3 肩

- 哑铃侧平举：肩外展，哑铃
- 坐姿肩推：垂直推，器械/哑铃
- 弹力带外旋：肩袖，弹力带
- 面拉：肩胛稳定/后束，绳索/弹力带

### 9.4 腿和臀

- 坐站：蹲，自重，低强度
- 杯式深蹲：蹲，哑铃/壶铃
- 腿举：蹲类，器械
- 罗马尼亚硬拉：髋铰链，哑铃/杠铃
- 臀桥：髋伸展，自重/杠铃
- 台阶上步：单腿，自重/哑铃
- 箭步蹲：单腿，自重/哑铃
- 腿弯举：腘绳肌，器械
- 提踵：小腿，自重/器械

### 9.5 核心

- 死虫：抗伸展，自重
- 平板支撑：抗伸展，自重
- 侧桥：抗侧屈，自重
- Pallof press：抗旋转，弹力带/绳索
- 鸟狗：稳定，自重

### 9.6 手臂

- 哑铃弯举：肱二头肌，哑铃
- 绳索下压：肱三头肌，器械
- 弹力带弯举：肱二头肌，弹力带
- 窄距俯卧撑：肱三头肌/胸，自重

## 10. 推荐引擎

### 10.1 输入

推荐引擎接收这些输入：

- `intent_text`：用户自然语言，如“我想练背”
- `selected_intensity`：低、中、高
- `user_profile`：训练经验、年龄段、目标、可用器械
- `pain_profile`：伤痛部位、严重程度、近期是否急性
- `recent_training`：最近训练部位、动作、强度、疼痛反馈
- `library_scope`：默认库、个人库、已审核个人库
- `favorite_exercises`：用户标心动作列表

### 10.2 自然语言解析

示例：“我想练背，但腰有点不舒服，今天在家，强度中等。”

解析为：

```json
{
  "goal_regions": ["背"],
  "movement_patterns": ["拉"],
  "excluded_or_cautious_regions": ["腰"],
  "equipment_context": ["自重", "弹力带", "哑铃"],
  "intensity": "medium",
  "session_type": "targeted"
}
```

### 10.3 过滤规则

硬过滤：

- `evidence_status = rejected_or_needs_edit`
- `evidence_status = user_unverified` 且用户未主动允许
- 与急性伤痛部位冲突的动作
- 无可用器械的动作
- 用户明确排除的动作

软降权：

- 轻微伤痛部位相关压力为 `medium` 的动作
- 最近 48 小时高强度训练过同一主要肌群
- 用户历史反馈“做完疼痛加重”的动作
- 技术复杂度超过用户经验等级的动作

加权排序：

- 目标部位匹配
- 动作类型覆盖
- 风险低
- 器械匹配
- 难度合适
- 有清晰媒体和说明
- 有高可信来源
- 用户标心喜欢
- 用户曾经完成且反馈良好

标心排序规则：

- 标心只在动作已通过硬过滤后生效。
- 当多个动作都满足目标部位、动作类型、安全和器械条件时，标心动作优先展示。
- 如果标心动作与当前伤痛部位冲突，系统仍应避开，并解释“已标心但因当前伤痛设置暂不推荐”。
- 如果标心动作属于 `user_unverified`，且用户未开启未验证动作推荐权限，系统仍不自动推荐。

### 10.4 “我想练背”推荐示例

输入：目标=背，强度=中，伤痛=腰轻微不适，可用器械=弹力带/哑铃。

输出：

1. 弹力带划船：3 组 x 10-15 次，RPE 6-7，休息 75 秒。
2. 单臂哑铃划船：3 组 x 8-12 次/侧，RPE 6-7，休息 90 秒；提示保持躯干支撑。
3. 弹力带下拉：2-3 组 x 10-15 次，RPE 6-7，休息 75 秒。
4. 俯身 Y/T/W 或面拉：2 组 x 12-15 次，轻强度，肩胛稳定。

避让说明：

- 暂不推荐杠铃俯身划船和大重量硬拉类动作，因为腰部不适时脊柱负荷和技术要求更高。
- 若训练中出现疼痛加重、麻木、放射痛或动作失控，应停止并寻求专业建议。

## 11. “不知道练什么”组合生成

### 11.1 组合类型

默认生成全身训练，因为它更适合大多数不知道练什么的用户，也更容易满足主要肌群覆盖原则。

模板：

- 低强度：3-4 个动作，全身基础，20 分钟内。
- 中强度：5-6 个动作，推/拉/蹲/髋/核心，30-45 分钟。
- 高强度：6-8 个动作，更高组数或更短休息，但不默认练到力竭。

### 11.2 强度映射

低强度：

- 动作数：3-4
- 组数：1-2
- 次数：8-15
- RPE：5-6
- 休息：60-90 秒
- 适合：恢复日、初学者、近期疲劳、轻微不适

中强度：

- 动作数：5-6
- 组数：2-3
- 次数：8-12 或 10-15
- RPE：6-8
- 休息：75-120 秒
- 适合：常规训练日

高强度：

- 动作数：6-8
- 组数：3-5
- 次数：5-10 或 8-12
- RPE：7-8，部分动作可接近 2-3 次剩余
- 休息：90-180 秒
- 适合：有经验、睡眠恢复良好、无明显伤痛

### 11.3 中强度全身组合示例

1. 杯式深蹲：3 x 8-12
2. 哑铃卧推或上斜俯卧撑：3 x 8-12
3. 坐姿划船或弹力带划船：3 x 10-12
4. 臀桥或罗马尼亚硬拉：2-3 x 8-12
5. Pallof press：2 x 10-12/侧
6. 死虫：2 x 8-10/侧

推荐理由：

- 覆盖下肢、推、拉、髋伸展和核心稳定。
- 适合大多数普通训练日。
- 可按器械替换动作。

## 12. 伤痛避让系统

### 12.1 设置项

每个伤痛部位记录：

- 部位：肩、腰、膝、髋、肘、腕、颈、踝
- 严重程度：轻微、明显、急性/严重
- 时间：今天、本周、长期
- 触发动作：过顶、深蹲、跑跳、髋铰链、推、拉等
- 专业建议：是否已有医生/物理治疗师建议

### 12.2 风险分级

动作库每个动作必须有 `joint_stress_tags`：

- `none`
- `low`
- `medium`
- `high`

推荐时：

- 急性/严重伤痛：相关 `medium` 和 `high` 动作硬过滤。
- 明显伤痛：相关 `high` 硬过滤，`medium` 降权并提示。
- 轻微不适：`high` 降权或替代，`medium` 可保留但需要说明。

### 12.3 示例避让

肩痛：

- 降权或过滤：重负荷过顶推举、双杠臂屈伸、深位飞鸟。
- 优先替代：墙壁俯卧撑、器械推胸、弹力带外旋、面拉。

腰痛：

- 降权或过滤：大重量硬拉、杠铃俯身划船、早安式。
- 优先替代：胸托划船、坐姿划船、臀桥、死虫、鸟狗。

膝痛：

- 降权或过滤：深幅度高负重深蹲、跳跃弓步、高冲击跳跃。
- 优先替代：坐站、箱式深蹲、臀桥、髋主导动作、可控台阶上步。

iOS：

1. 接收内容
   - URL、标题、描述、图片/GIF/视频、纯文本。
2. 抽取候选素材
   - Open Graph 封面。
   - 页面内视频/GIF候选。
   - 用户直接分享的图片/GIF/视频。
3. 拆解动作说明
   - OCR：从图片或截图抽取文字。
   - 语音转文字：从视频讲解中提取文本。
   - 页面解析：抽取标题、正文、小标题和列表。
   - LLM 结构化：识别动作名称、步骤、目标部位、器械、注意事项。
4. 风险和证据处理
   - 默认标为 `user_unverified`。
   - 若来源为可信动作库并能匹配默认动作，可建议合并到已有动作。
   - 若动作高风险或信息不完整，标为 `rejected_or_needs_edit`。
5. 用户确认
   - 展示候选名称、GIF/图片、讲解、标签、风险提示。
   - 用户确认后进入“我的动作”。

### 13.3 版权和平台限制

- 保存个人学习用途的链接和用户提供内容。
- 不承诺能下载所有平台视频或 GIF。
- 不绕过登录、DRM、付费墙、反爬机制。
- 默认保存来源链接，保留出处。

### 14.6 首版用户流程

流程 A：用户说“我想练背”

1. 首页输入“我想练背”。
2. 系统解析为目标部位=背，动作类型优先=拉，训练类型=局部训练。
3. 系统读取伤痛设置、可用器械、训练经验和最近训练记录。
4. 推荐引擎先过滤不可用器械和高风险动作，再按目标匹配、风险低、说明清晰、来源可信排序。
5. 推荐结果页展示背部训练组合，并说明推荐理由和避让理由。
6. 用户可开始训练、替换动作、收藏组合或查看单个动作详情。
7. 训练结束后记录完成情况、RPE 和疼痛反馈，用于下次推荐。

流程 B：用户不知道练什么

1. 首页点击“不知道练什么”。
2. 用户只选择训练强度：低 / 中 / 高。
3. 系统检查最近训练记录和伤痛设置。
4. 默认生成全身组合，覆盖推、拉、下肢、髋和核心中的多个基础模式。
5. 如果某部位近期训练负荷高或存在伤痛，系统替换为低风险动作或降低该部位负荷。
6. 推荐结果页展示完整组合、预计时长、动作顺序、组数次数、休息时间和安全提示。

流程 C：用户手动添加动作

1. 动作库点击“新增动作”。
2. 用户上传 GIF、图片、视频链接或文字说明。
3. 系统提示用户填写或确认部位、动作类型、器械、难度和注意事项。
4. 动作保存到“我的动作”，默认 `evidence_status = user_unverified`。
5. 未验证动作可浏览、收藏、手动加入训练，但默认不进入自动推荐。

流程 D：从其他软件一键保存动作

1. 用户在外部 App 分享链接、图片、GIF、视频或文本到本 App。
2. 内容进入“待确认动作”。
3. 系统提取素材候选、标题、来源链接和动作讲解文本。
4. 系统尝试结构化动作名称、部位、动作类型、器械、步骤和注意事项。
5. 用户在收件箱确认、编辑、合并到已有动作或丢弃。
6. 确认后进入“我的动作”，仍按证据等级决定是否能被推荐。

流程 E：用户设置伤痛部位

1. 设置页选择伤痛部位和严重程度。
2. 系统保存触发动作、持续时间和是否已有专业建议。
3. 之后每次推荐都会先读取伤痛资料。
4. 急性或严重伤痛触发硬过滤；轻微不适触发降权和替代建议。
5. 推荐页必须说明“为什么避开某些动作”。

## 15. 训练记录和反馈

每次训练结束后记录：

- 完成动作
- 实际组数次数
- 主观强度 RPE
- 是否跳过或替换
- 训练后疼痛变化：无变化、减轻、加重
- 备注

推荐引擎使用反馈：

- 做完疼痛加重的动作自动降权。
- 连续完成且反馈良好的动作升权。
- 用户标心的动作在通过安全过滤后升权。
- 最近高强度训练过的肌群降低次日推荐概率。

## 16. 安全文案

首次设置伤痛时：

“这里用于帮助推荐避开可能刺激的动作，不用于诊断或治疗。如果你有急性损伤、明显肿胀、麻木、放射痛、胸闷、头晕，或疼痛持续加重，请先咨询医生或物理治疗师。”

推荐页避让说明：

“已根据你的伤痛设置避开部分动作。训练中如疼痛加重，请停止当前动作。”

未验证动作提示：

“这是你的自定义动作，尚未通过科学来源或专业审核。默认不会进入自动推荐。”

## 17. 技术架构建议

### 17.1 客户端

第一版可用跨平台移动框架：

- React Native / Expo：适合快速做 iOS + Android 原型和分享入口。
- Flutter：适合高一致性 UI 和复杂动画。

若优先实现外部分享能力，React Native 需要额外原生模块；Flutter 也需要平台通道。真正上架版本应分别处理 iOS Share Extension 和 Android Intent。

### 17.2 后端

核心服务：

- Exercise Library Service：动作库、媒体、来源、版本。
- Recommendation Service：解析目标、过滤、排序、生成组合。
- Ingestion Service：外部分享内容解析、OCR、转写、结构化。
- Safety Rules Service：伤痛避让和风险标签规则。
- Evidence Registry：来源、版本、证据等级、审阅状态。

### 17.3 本地优先

动作库、设置和最近训练应支持本地离线读取。外部内容拆解、OCR、转写和 LLM 结构化可以异步处理。

## 18. 验证清单

### 18.1 功能验收

- 输入“我想练背”能返回背部训练动作。
- 用户标心的动作在满足安全、器械和目标条件时优先出现在推荐结果中。
- 设置肩痛后，推荐减少或避开高风险肩部动作，并显示原因。
- 设置腰痛后，背部训练不默认推荐大重量硬拉和杠铃俯身划船。
- 点击“不知道练什么”并选择强度后，能生成完整训练组合。
- 用户上传 GIF/图片和说明后，动作进入“我的动作”。
- 外部分享 URL 或图片后，动作进入“待确认动作”。
- 未验证动作默认不进入自动推荐。

### 18.2 科学验收

- 默认动作都有来源链接或来源类型。
- 默认训练组合覆盖推、拉、下肢、髋、核心中的多个基础模式。
- 强度处方包含动作数、组数、次数、RPE 和休息时间。
- 训练推荐遵守“低起点、慢进阶”的安全原则。
- 有慢病、急性伤痛或严重症状时显示咨询专业人士提示。

### 18.3 质量验收

- 推荐结果必须解释“为什么推荐”和“为什么避开”。
- 用户可以替换任一动作。
- 没有足够安全动作时，系统不强行推荐，应提示降低强度或调整条件。
- 外部内容解析失败时，仍保存原始链接和素材，允许用户手动补充。

### 18.4 推荐规则验收样例

| 场景 | 输入 | 期望结果 |
| --- | --- | --- |
| 背部训练，无伤痛 | “我想练背”，中强度，有高位下拉器和哑铃 | 推荐垂直拉 + 水平拉 + 肩胛稳定动作，显示组数、次数、RPE、休息和来源 |
| 背部训练，腰轻微不适 | “我想练背”，中强度，腰=轻微 | 不默认推荐大重量硬拉、杠铃俯身划船；优先坐姿划船、胸托划船、弹力带划船等低腰负荷动作 |
| 不知道练什么，低强度 | 点击“不知道练什么”，强度=低，训练经验=新手 | 生成 3-4 个全身基础动作，RPE 5-6，动作说明清晰，不出现高技术复杂度动作 |
| 不知道练什么，高强度但有肩痛 | 强度=高，肩=明显 | 不推荐高风险过顶推举和双杠臂屈伸；如安全动作不足，应降级强度或提示调整条件 |
| 外部保存视频 | 从外部 App 分享动作视频链接 | 进入待确认动作，保留来源链接，提取标题、封面、媒体候选和动作讲解；默认标记为未验证 |
| 用户上传 GIF | 上传 GIF + 手写说明 | 进入我的动作，要求补充部位、动作类型、器械、风险标签；默认不进入自动推荐 |
| 未验证动作推荐权限关闭 | 用户有 5 个自定义未验证动作 | 自动推荐只使用默认库和已审核动作；未验证动作只可手动加入 |
| 标心动作优先 | 用户标心“高位下拉”，输入“我想练背”，无肩痛且有高位下拉器 | 高位下拉在同等安全和目标匹配条件下优先推荐 |
| 标心动作与伤痛冲突 | 用户标心“坐姿肩推”，设置肩=明显，请求练上肢 | 不因标心绕过伤痛避让；解释该动作已标心但当前暂不推荐 |
| 严重疼痛 | 腰=急性/严重，用户请求练下肢高强度 | 不强行生成高强度下肢训练，提示降低强度、选择恢复训练或咨询专业人士 |

## 21. 审阅重点

请优先看这 5 个产品决策：

1. 第一版是否按“推荐引擎型 MVP”推进，而不是单纯动作库或 AI 聊天教练。
2. 未验证的个人动作是否默认不进入自动推荐。
3. 伤痛功能是否只做避让和提示，不做诊断或康复处方。
4. “不知道练什么”是否默认生成全身训练，而不是每天随机推某个部位。
5. 外部一键保存是否接受“先进入待确认队列”，而不是自动加入正式动作库。

如果这 5 点成立，后续原型和实现计划就可以围绕它们展开。
