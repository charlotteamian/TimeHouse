# 时光屋动作持续复核

用户已授权持续复核与修图，必要时重制。优先徒手、哑铃、TRX，其后处理其余器械；动态封面和运动中示范保持动态。以质量通过为准，未通过的条目继续显示未复核。

## 每次续跑

1. 先读 `assets/motion_repairs/review-workflow-state.json` 和当前批次 README／结果，运行 `python3 scripts/review_workflow_next.py`。有未完成批次就续做，不重复开新批次。不要重读整段对话、整个资料库或历史生成目录。
   新批次可用 `/opt/homebrew/Caskroom/miniforge/base/bin/python3 scripts/prepare_review_batch.py <批次ID>` 自动保存原件、选中条目和逐帧预览；已有批次会拒绝覆盖。该脚本不作复核判定。
2. 每批核查 8–12 条，优先检查现有阶段图。候选中轮换徒手、哑铃和可处理的 TRX；同时关注脚本列出的缺图种子条目和 TRX 暂缓项，有新修复方法再尝试其中一项，不把这些待办遗忘。查看全部帧、完整循环和至少两个应固定的支撑点；核对名称、变式、器械及额外支撑物、肌群、步骤、模式、单侧计次和训练伤痛筛选。资料只查匹配的权威／教练原始来源，并保存 URL。
3. 原有四帧位置不一致时，优先修正封装时的偏移。只有所有固定点能同时对齐才采用整体平移，不得用拉伸人体、整图光流、插帧或模糊掩盖问题。固定支点有独立变形、错姿势或缺图时才进入重制。
4. 每轮最多重制 1 个动作，最多生成 1 次加 1 次针对性精修，使用内置 imagegen。先复用已保存的参考和短提示词；没有新修复方法时不反复生成同一失败项。额度不可用时记录恢复时间，继续查现有图，不循环重试、不切换付费 API。质量失败项记录具体原因和尝试次数，放入 `deferred_ids`，有新方法再取出。生成成功不能直接授予已复核。
5. 每批保留修改前原件、选中条目、逐帧预览、支撑点测量、来源和人工视觉判定。先在未复核状态验证修改后的资料、器械筛选和实际播放，均通过后才向 `exercise_reviews.json` 写入已复核记录；绑定当前资料与图片哈希。随后验证最终安装包内的已复核筛选。补图不等于复核，种子条目也必须有有效的资料指纹支持。
6. 修改资料／素材后运行复核审计、相应数据检查和构建。新增已复核或修改训练逻辑须验证筛选、动态播放、训练可选、关节负荷和单侧计次；使用现有模拟器 QA，按顺序运行并恢复偏好。测试按改动范围选择，通过后不无故重跑。
7. 每完成一批才制作一个可覆盖安装的版本，验签及 APK 内资料／素材哈希。上一版安装包保留；不在每个动作完成时打包。记录当前版本、交付路径、已复核数量、剩余问题和下一步到状态文件，批次结束将 `active_batch.phase` 标记为 `complete`，供续跑脚本选择下一批。
8. 没有可处理条目时，区分“全部通过”和“仅剩需要新方法的失败项”，如实记录并暂停对应 heartbeat；未复核条目不能为完成进度而提前通过。实际设备播放效果与模拟器验证分别记录。

## 节省上下文

状态 JSON 是续跑入口；全量资料是动作定义的事实来源，复核账本是状态来源。脚本只给出下一批候选，不自动做视觉判定、不修改复核标签。优先小批缩略图初筛，再对疑点放大；不同动作不共享未经核实的通过结论。相同状态下保持安静，有可用新版本、实质完成、失败或需要用户处理时再通知。
