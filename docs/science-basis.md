# 科学依据说明（训练 + 饮食）

这份文档把 App 里每一条「推荐」背后引用的指南和参数集中列出，方便核对与升级。
所有参数常量都集中在 `app/src/main/java/com/restartday/fitness/domain/GuidelineRefs.java`，
UI 与生成逻辑只引用这些常量，改依据只改一处。

> 免责声明：本 App 的评估与推荐是基于公开指南的通用建议，不构成医学诊断或个体化
> 处方。有基础疾病、伤痛、孕期或用药情况，请以医生/注册营养师/物理治疗师意见为准。

## 一、训练

### 1. 运动前安全筛查
- **PAR-Q+（2021）身体活动准备问卷**：7 条安全筛查题，任一「是」→ App 建议先就医，
  且把周期计划的强度上限降到「低」。
- 代码：`FitnessAssessment.evaluate()` + `AssessmentInput.anySafetyFlag()`。

### 2. 训练水平分级
- 以训练史为主（累计月数 + 近 3 个月每周次数），体能自测（俯卧撑/平板/深蹲）只用于
  「偏弱时降一级起步」，宁低勿高。参考 ACSM 体适能评估思路，属简化自评。
- 分级门槛：初级 <6 个月或每周 <2 次；中级 6–24 个月且每周 ≥2 次；高级 ≥24 个月且每周 ≥3 次。
- 代码：`FitnessAssessment.levelFromHistory()` / `capByFitnessTests()`。

### 3. 周期化结构（8 周）
- **NSCA《肌力与体能训练精要》**：线性周期化 适应期(第 1–2 周) → 发展期(第 3–5 周)
  → 强化期(第 6–7 周) → 减载/重测周(第 8 周)。
- **减载**：每 3–6 周安排一个降量周管理疲劳（NSCA/ACSM 共识）。
- 代码：`ProgramBuilder.build()` 的 4 个 `ProgramPhase`。

### 4. 训练频率与分化
- **ACSM《运动测试与处方指南》第 11 版**：每个大肌群每周训练 2–3 天。
- **Schoenfeld 等 2016 荟萃分析**：同等周训练量下，每肌群每周 ≥2 次优于 1 次。
- 分化随每周天数自动选择，且**任何一种都保证每个大肌群每周被练到 ≥2 次**
  （由 `ProgramBuilderTest.everyMuscleTrainedAtLeastTwiceAWeekOnResistanceSplits()` 断言守护）：
  - 2 天：全身 A / 全身 B
  - 3 天：全身 A / B / C
  - 4 天：上肢 / 下肢 ×2（体适能与减脂目标会插入有氧核心日）
  - 5 天：推 / 拉 / 腿 + 上肢 / 下肢
- 代码：`ProgramFocus`（部位与动作模式标签）+ `ProgramBuilder.splitFor()`。

### 5. 组数 / 次数 / RPE / 休息（按目标 × 阶段）
按 ACSM/NSCA 的目标别区间取值（示例为发展期/强化期典型值）：
- **增肌**：8–12 次为主，RPE 6–9，休息 90–120 秒。
- **力量**：3–8 次，RPE 7–9，休息 150–180 秒（大负荷）。
- **减脂**：10–15 次、休息 60 秒提高密度，力量维持强度防掉肌肉。
- **体适能**：8–12 次，RPE 6–8，休息 90 秒。
- 初级统一 −1 组、避开大重量低次区间；高级发展/强化期 +1 组。
- 代码：`ProgramBuilder.developPrescription()` / `intensifyPrescription()` / `adjustSets()`。

### 6. 渐进超负荷
- **NSCA**：当能以标准动作完成目标次数上限时，负荷渐进 2–10%（小肌群取低值）；
  连续两周完不成下限则减重 5–10%。
- 代码：`ProgramBuilder` 的 `progression` 字符串。

### 7. 有氧（减脂 / 体适能目标叠加）
- **ACSM 与美国《身体活动指南》PAGA 2018**：每周 150–300 分钟中等强度有氧，
  或 75–150 分钟高强度；每周至少 2 天抗阻训练。
- 减脂目标：发展期 ≥150 分钟/周，强化期提到 ~250 分钟/周（含 1–2 次间歇）。
- 代码：`ProgramBuilder.aerobicMinutes()` / `aerobicNote()`。

### 8. 每日训练的动作怎么来
- 周期计划只描述「结构」；**某天的具体动作在开练时按当天部位现选**，
  复用既有 `RecommendationEngine` 的伤痛/器械/证据过滤，处方由阶段统一覆盖。
- 代码：`MainActivity.startProgramSession()`。

## 二、饮食

### 1. 能量目标
- **基础代谢 BMR：Mifflin-St Jeor 公式（1990）**
  - 男：10×体重(kg) + 6.25×身高(cm) − 5×年龄 + 5
  - 女：10×体重 + 6.25×身高 − 5×年龄 − 161
- **TDEE = BMR × 活动系数**（久坐 1.2 … 极高 1.9）。
- **目标热量**：减脂 −400 kcal/天（约每周 0.3–0.5kg），不低于安全下限（男 ≥1500 / 女 ≥1200
  且不低于 BMR）；增肌 +300 kcal/天；力量/体适能维持。
- 代码：`NutritionPlanner.plan()`，由 `NutritionPlannerTest` 用已知值校验。

### 2. 蛋白质
- **中国营养学会 DRIs**：一般成年人 RNI 男 65g、女 55g/天。
- **Morton 等 2018 荟萃分析 / ISSN 立场声明**：抗阻训练人群 1.6–2.2 g/kg/天。
- App 取值：体适能 1.2 g/kg（高于 RNI 以配合活动）、增肌/力量 1.8、减脂 2.0（保肌）。
- BMI ≥ 28 时按「BMI 24 对应体重」估算，避免按超重体重放大摄入。

### 3. 脂肪 / 碳水
- **中国营养学会 DRIs**：脂肪供能比 20–30%（App 取 27%）；添加糖 <50g，最好 <25g。
- 碳水补足剩余能量，设 100g/天 下限保证训练表现与纤维来源。

### 4. 膳食纤维 / 水 / 盐
- **《中国居民膳食指南(2022)》与 DRIs**：膳食纤维 25–30g/天；饮水 1500–1700ml/天；盐 <5g/天。
- 代码：`EnergyPlan` 的 `fiberMin/MaxG`、`waterMin/MaxMl` 常量。

### 5. 平衡膳食宝塔（每日各类食物克数）
- **《中国居民膳食指南(2022)》平衡膳食宝塔**成人推荐区间：
  谷类 200–300g（含全谷物和杂豆 50–150g）、薯类 50–100g、蔬菜 300–500g（深色占一半）、
  水果 200–350g、鱼禽肉蛋 120–200g（每周 ≥2 次水产、每天一个蛋）、奶及奶制品 300–500g、
  大豆及坚果 25–35g、油 25–30g。
- App 按你的目标热量在各区间内**线性内插**成当日克数目标，作为「今日打卡」的对照。
- **克数口径一律是生重/干重**，这是指南的原始口径，也是全 App 的统一约定：
  一碗熟米饭（约 200g）记 `GRAIN 80`（生米），100g 面包记 `GRAIN 70`（面粉当量），
  100g 北豆腐记 `SOY_NUT 20`（大豆当量），10g 奶酪 ≈ 100g 液态奶。
  按熟重直接填会高估 2–3 倍，所以所有预设都预先折算好，AI 估算的提示词里也强制这一条。
- 「零食·其他」（`FoodGroup.OTHER`）是宝塔之外的额外热量（含糖饮料、糕点、酒），
  推荐区间为 0，只记录不设正向目标，UI 里显示为单一数值而不是「已吃/目标」。
- 代码：`FoodGroup`（区间常量 + ± 步长）+ `PagodaTargets.forEnergy()`。

### 5b. 「记一餐」快速录入（外卖 / 零食 / 估不准的一餐）
- 问题：外卖和零食没法按类别估克数——没人能看着一份黄焖鸡米饭说出各类别多少克。
  强求精度的直接后果是干脆不记，而漏记的一天比 ±30g 的误差严重得多。
- 方案：录入单位改成**「一份菜」而不是「多少克」**，折算由 App 承担。三条路径：
  1. **常见外卖模板**（16 个）：黄焖鸡米饭、兰州拉面、麻辣烫、汉堡套餐、火锅等，
     每个存一份宝塔生重构成，点一下加一份，支持 0.5 份步长。
  2. **份量法**（17 个）：一拳米饭、一掌心肉、两手捧菜、一拇指油等手估单位，
     用来拼模板里没有的组合。以上两条完全离线，不依赖 AI 和网络。
  3. **AI 估算**（可选）：一句话描述或一张餐食照片 → 拆成宝塔生重克数 → 用户确认后写入。
     提示词强制生重口径，并兜底「全谷物不得超过谷类」。需自行开启 AI 并填 Key。
- 三条路径都汇入同一个待确认草稿（`MealDraft`），确认后才一次写进当日打卡。
- 预设数据：`assets/quick_meals_cn.json`（热量为《中国食物成分表》常见值估算，仅供对照）。
- 代码：`MealPreset` / `MealDraft` / `QuickMealLoader`，由 `MealDraftTest` 守护。

### 6. 食谱推荐（按缺口，非随机）
- 内置 26 个食谱按宝塔结构设计（`assets/recipes_cn_guideline.json`），
  每份标注营养估算、宝塔构成、搭配依据与指南引用。
- 推荐 = 按「今日还差什么」评分：蛋白缺口权重最高，其次蔬菜/全谷物/奶/大豆缺口 +
  纤维加分，超出剩余热量扣分，训练日偏好高碳水高蛋白。
- 代码：`RecipeScorer.rank()`，由 `NutritionPlannerTest` 的评分用例守护。
- 食谱营养为《中国食物成分表》常见值估算，仅供对照参考。

## 三、测试与校验

```bash
# 领域逻辑单元测试（含训练/营养全部断言）+ 数据集校验
./scripts/run_domain_tests.sh
```

包含：`RecommenderTest`、`ProgramBuilderTest`、`NutritionPlannerTest`、`MealDraftTest`、
动作数据集校验、`validate_recipe_dataset.py`（食谱热量与宏量一致性、宝塔覆盖、每餐段 ≥3 个）、
`validate_quick_meals.py`（预设 id 唯一、类别合法、克数为正、热量与构成量级一致；
「零食·其他」占比过半的条目跳过热量校验并在输出里点名，因为这个桶从啤酒到巧克力
能量密度差 15 倍，套任何单一密度都是假校验）。
